# Contributing to rboto

Thanks for your interest in rboto. This guide covers the setup, the rules that make the
project work, and the checks a change must pass.

## Before you start

rboto is a code generator plus its generated output. Most of the Python and Rust in this
repository is produced by `rboto-codegen` from pinned Smithy models and pinned AWS Rust SDK
crates. Read these before changing code:

1. [`.ai/invariants.md`](.ai/invariants.md) - the rules every change must preserve.
2. [`.ai/architecture.md`](.ai/architecture.md) - repository boundaries and sources of truth.
3. [`.ai/codegen.md`](.ai/codegen.md) - which layer to change for which kind of fix.
4. [`ADR/`](ADR/) - the architecture decisions and their rationale.

The short version:

- **Never edit generated files.** Files marked `Generated by rboto-codegen. DO NOT EDIT.`
  are overwritten on the next generation. Fix the descriptor, parser, generator, or
  template instead.
- **Regenerate every service** after a generic generator or template change, and review
  the diff for all of them.
- **Keep one-to-one alignment** between each generated Python method and its PyO3
  counterpart.
- **Preserve the contract**: async-only methods, keyword-only parameters, strict typing,
  Rust-owned immutable outputs, single-move stream ownership, and modeled exceptions.

## Requirements

- Python 3.12 or newer
- Rust (stable, see `rust-version` in `Cargo.toml`) with `cargo fmt` and `cargo clippy`
- A C compiler supported by PyO3
- Docker, for LocalStack integration tests

## Setup

```bash
git clone https://github.com/ferrumio/rboto.git
cd rboto

python3 -m venv .venv
.venv/bin/pip install maturin pytest mypy pyright ruff
.venv/bin/pip install -e codegen -e packages/rboto
```

Build the native extensions in editable mode, one per service:

```bash
(cd packages/rboto-s3 && ../../.venv/bin/maturin develop --locked)
(cd packages/rboto-sns && ../../.venv/bin/maturin develop --locked)
(cd packages/rboto-sqs && ../../.venv/bin/maturin develop --locked)
(cd packages/rboto-dynamodb && ../../.venv/bin/maturin develop --locked)
```

## Making a change

### Changing generated code

1. Edit the correct source layer:
   - Service metadata or feature toggle: `codegen/src/rboto_codegen/services/*.toml`
   - Descriptor fields: `model.py`, `registry.py`
   - Type conversion or operation behavior: `generator.py`
   - Repeated file structure: a template under `codegen/src/rboto_codegen/templates/`
2. Regenerate all services:
   ```bash
   .venv/bin/rboto-codegen generate --all
   ```
3. Review the generated diff for every service, including unexpected removals.
4. Rebuild the native extensions before running bridge or LocalStack tests.

Do not add service-name branches to generic generation. Declare service differences in the
service TOML first.

### Changing handwritten code

Handwritten code lives in `crates/rboto-core`, `packages/rboto/src/rboto`, the codegen
package, tests, examples, and docs. Changes there follow the normal review process.

### Adding a new AWS service

Add a service TOML with the pinned model and crate version, run `fetch-model` and
`generate`, add the service to the facade, CI, and release workflows, and add
representative LocalStack tests. See ADR-0001 and ADR-0006.

## Required checks

Run every check in [`.ai/commands.md`](.ai/commands.md) before opening a pull request.

Python and codegen:

```bash
.venv/bin/ruff check codegen/src codegen/tests packages/rboto/src packages/rboto/tests tests examples benchmarks .github/scripts
.venv/bin/mypy --strict codegen/src codegen/tests packages/rboto/src packages/rboto-s3/python packages/rboto-sns/python packages/rboto-sqs/python packages/rboto-dynamodb/python tests/typecheck examples
.venv/bin/pyright
.venv/bin/pytest codegen/tests packages/rboto/tests -q
```

Rust:

```bash
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

LocalStack integration (requires a running LocalStack on port 4566 and rebuilt
extensions):

```bash
export AWS_ACCESS_KEY_ID=testing
export AWS_SECRET_ACCESS_KEY=testing
export AWS_REGION=us-east-1
export AWS_ENDPOINT_URL=http://localhost:4566

.venv/bin/pytest tests/integration packages/rboto-s3/tests packages/rboto-sns/tests packages/rboto-sqs/tests packages/rboto-dynamodb/tests packages/rboto/tests -q
```

Test rules are in [`.ai/testing.md`](.ai/testing.md). In short: pass `endpoint_url`
explicitly, use unique resource names, clean up in `finally`, test across the
Python-to-Rust boundary, and do not claim AWS compatibility from LocalStack alone.

## Pull requests

- Use [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`,
  `docs:`, `ci:`, `chore:`, ...). The changelog is generated from commit messages.
- Keep generated-code changes and generator changes in the same pull request so the
  generated diff can be reviewed against its cause.
- Do not commit credentials, private endpoints, wheels, or build artifacts.
- Document architecture changes in a new ADR under `ADR/`. Accepted ADRs are immutable
  except for status and links.
- Public documentation goes in `docs/`; internal decisions in `ADR/`; agent context in
  `.ai/`.

### Checklist

- [ ] Source layer changed, not generated files
- [ ] All services regenerated (for generic changes) and diffs reviewed
- [ ] Python lint, strict typing, and unit tests pass
- [ ] Rust format, tests, and Clippy pass
- [ ] Bridge and LocalStack tests pass for affected services
- [ ] Docs or ADR updated if behavior or architecture changed

## AI-assisted contributions

AI tools are welcome. The rules do not change: understand what was generated, follow the
project patterns, and run the complete verification. [`AGENTS.md`](AGENTS.md) and
[`.ai/`](.ai/) are the entry points for coding agents. Pull requests with unverified or
unexplained generated code may be closed.

## Reporting problems

Open an issue on GitHub for bugs and feature requests. For security issues, follow
[`SECURITY.md`](SECURITY.md).
