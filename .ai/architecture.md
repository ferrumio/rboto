# Architecture

## Runtime path

```text
Typed async Python method
        |
        v
Generated Python parameter dictionary
        |
        v
Generated PyO3 client method
        |
        v
Tokio future and AWS Rust SDK request
        |
        v
AWS or LocalStack
```

## Repository boundaries

- `packages/rboto`: pure-Python facade, session API, shared exceptions, and extras.
- `packages/rboto-<service>`: generated Python API, stubs, and package metadata.
- `crates/rboto-core`: shared Rust runtime and error normalization.
- `packages/rboto/src/rboto/config.py`: validated, immutable request/credential settings.
- `crates/rboto-<service>`: generated PyO3 adapter plus minimal handwritten runtime.
- `codegen`: Smithy loading, Rust crate parsing, alignment, generation, and templates.
- `codegen/models`: pinned Smithy models.
- `tests/integration`: compiled bridge contracts and LocalStack behavior.
- `ADR`: internal architecture decisions.
- `docs`: public user documentation only.

## Public client imports

Client classes are the primary public API: `from rboto import S3Client`.
The generated facade lazily imports the selected service and has an explicit
generated stub for static tooling. Constructors and compatibility factories
share `Session` resolution.

Descriptors use `client_class` for the public Python name. An optional
`native_client_class` preserves the native backend name and original service
exception names; the old client name remains a Python compatibility alias.
Do not rename native symbols or modeled exception bases as a side effect of
changing a public client name. See ADR-0013.

## Operation middleware

Configured interceptors form an async `(request, next) -> response` chain in
`rboto.interceptors`. They may change parameters, block or skip native dispatch,
and replace a response. Generated methods unwrap the output while preserving
public signatures and native return contracts. A private metadata sink receives
bounded retry details from `rboto-core`. Empty configuration keeps direct dispatch.
See ADR-0014 for continuation lifetime, exceptions, and streaming behavior.

`configure_logging()` in `rboto.logging` enables ready-made JSON logs globally.
Generated methods resolve the internal logging middleware at invocation time, so
service levels and disabling affect existing clients. `get_logger()` exposes each
`rboto.<service>` logger. See ADR-0015 for configuration and delivery semantics.

## Sources of truth

The service TOML, Smithy model, pinned AWS Rust crate, generator, and templates are sources
of truth. Files marked `Generated by rboto-codegen` are reviewable artifacts, not editing
targets.

See ADR-0001 through ADR-0004 for the rationale behind these boundaries.

ADR-0012 defines client configuration and typed failure mapping. Settings resolve
once per native client; Session does not share native caches across wheels.
ADR-0016 defines per-client proxy/TLS transport and the credential-cache boundary.

ADR-0018 separates request types from dictionary response types recursively.
Response nullability follows Rust fields; unknown union variants are output-only.
Response enums retain their known literals plus the erased `UnknownEnumValue`
string type for future SDK values. Input lists accept sequences, while maps
continue to require dictionaries.

ADR-0019 defines `client.paginators`, generated from validated Smithy traits and
descriptor supplements. The private Python iterator calls public operations
page by page, preserving middleware and native responses. There is no public
`inputs` adapter namespace.
